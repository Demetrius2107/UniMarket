## 1. 对接总览

| 第三方 | 用途 | 关键前置 | 对接阶段 |
|--------|------|----------|----------|
| 微信公众号 | OAuth 扫码登录 | 认证服务号 + 网页授权域名 + 回调域名 | Phase 1 |
| 微信支付 | C 端支付 | 商户号 + APIv3 密钥 + 证书 | Phase 1 |
| 支付宝 | C 端支付（沙箱） | 沙箱应用 + RSA2 公私钥 | Phase 1 |
| 快递鸟 | 物流轨迹查询/订阅 | 商户 ID + API key + 回调白名单 | Phase 7 |

**通用约定**：
- 所有第三方密钥/证书/回调地址走 Nacos 配置，**禁止硬编码**（见《配置规范-Nacos配置清单》）。
- 回调处理统一在 `trigger/portal`（WeixinPortalController / AlipayNotifyController），先验签后业务。
- 第三方响应一律超时保护 + 失败补偿（支付掉单补偿 / 通知重试）。

## 2. 微信公众平台（OAuth 扫码登录）

### 2.1 流程（源自 SDS §9.1）

```
获取 access_token → 生成 ticket → 展示二维码
  → 用户扫码 → 微信回调 → 缓存 ticket→openId
  → 前端轮询 check_login → 签发 JWT
```

### 2.2 前置准备

| 项 | 说明 |
|----|------|
| 公众号类型 | 认证服务号（有网页授权权限） |
| 网页授权域名 | 公众号后台配置（用于 OAuth 回调） |
| JS 安全域名 | 配置前端域名 |
| 内网穿透 | 本地联调需公网回调地址（见《部署手册》§6） |

### 2.3 关键接口与配置项

| 接口/配置 | 说明 |
|-----------|------|
| `wechat.app-id` | 公众号 AppID |
| `wechat.app-secret` | AppSecret（**仅服务端持有**） |
| `GET /cgi-bin/token` | 获取全局 access_token（2 小时有效，需缓存+刷新） |
| `POST /cgi-bin/qrcode/create` | 生成带参二维码 ticket（临时二维码，可配过期时间） |
| `GET /cgi-bin/showqrcode?ticket=` | 展示二维码图片 |
| 扫码回调 | 微信推送 openId（回调地址需配置到白名单） |
| `GET /sns/oauth2/access_token` | OAuth2 授权换取 openId/unionId |

### 2.4 实现要点

- access_token 需全局缓存（Redis），过期前刷新，避免频繁获取。
- 二维码 ticket 有效期建议 ≤ 5 分钟（与轮询窗口一致）。
- 扫码回调事件与轮询解耦：回调只写 Redis（`user:ticket:{ticketId}` → openId），轮询接口读缓存后查/建用户。
- 同一用户（openId）幂等：查库不存在才创建。

## 3. 微信支付

### 3.1 前置准备

| 项 | 说明 |
|----|------|
| 商户号 | 微信支付商户平台申请 |
| APIv3 密钥 | 平台设置，用于签名 |
| 商户证书 | 商户 API 证书（p12/pem），用于请求签名 |
| 回调地址 | 商户平台配置 `https://<域名>/api/v1/order/wxpay_notify` |

### 3.2 核心接口

| 接口 | 说明 |
|------|------|
| `POST /v3/pay/transactions/jsapi` | JSAPI 下单（H5 可走 H5 支付） |
| `POST /v3/pay/transactions/query` | 订单查询（掉单补偿用） |
| 支付结果通知 | 异步回调，需解密（AES-256-GCM）与验签 |

### 3.3 回调处理约定

- 回调需验证签名（微信支付平台证书）并解密报文。
- 幂等：以 `out_trade_no`（本系统支付单号）为幂等键，重复通知直接返回成功应答。
- 应答：成功返回 `{"code":"SUCCESS"}`；失败返回 `{"code":"FAIL","message":"..."}`（微信会重试）。
- 掉单补偿：定时任务主动查单（见《MQ 与定时任务规范》§8）。

### 3.4 配置项

| 配置 | 说明 |
|------|------|
| `wxpay.mch-id` | 商户号 |
| `wxpay.api-v3-key` | APIv3 密钥 |
| `wxpay.private-key-path` | 商户私钥路径（或 base64） |
| `wxpay.cert-serial-no` | 商户证书序列号 |
| `wxpay.notify-url` | 回调地址 |

## 4. 支付宝开放平台（沙箱支付）

### 4.1 前置准备

| 项 | 说明 |
|----|------|
| 沙箱应用 | 开放平台沙箱环境创建应用，获取 AppID |
| RSA2 密钥对 | 应用公钥/私钥 + 支付宝公钥（沙箱专用） |
| 沙箱账号 | 买家/卖家测试账号（支付宝沙箱控制台获取） |
| 回调地址 | 应用配置 `https://<域名>/api/v1/order/alipay_notify` |

### 4.2 核心接口

| 接口 | 说明 |
|------|------|
| `alipay.trade.page.pay` | 电脑网站支付（返回表单 HTML 前端直接提交） |
| `alipay.trade.query` | 交易查询（掉单补偿） |
| 异步通知 | 回调通知，需验签（RSA2） |

### 4.3 回调处理约定

- **验签必须严格**：用支付宝公钥 + RSA2 校验签名，验签失败拒绝处理并记录告警。
- 校验 `trade_status = TRADE_SUCCESS`（仅此状态视为成功；TRADE_FINISHED 视为终态）。
- 幂等：以 `out_trade_no` 为幂等键，重复回调不重复处理。
- 应答：成功返回字符串 `success`（**不是 JSON**，返回其他内容支付宝会重试）。
- 金额校验：回调金额与支付单金额比对，不一致告警（防篡改）。

### 4.4 配置项

| 配置 | 说明 |
|------|------|
| `alipay.app-id` | 沙箱/正式 AppID |
| `alipay.private-key` | 应用私钥（PKCS8） |
| `alipay.alipay-public-key` | 支付宝公钥 |
| `alipay.gateway-url` | 沙箱 `https://openapi-sandbox.dl.alipaydev.com/gateway.do` |
| `alipay.notify-url` | 异步通知地址 |
| `alipay.return-url` | 同步跳转地址（仅展示用，以异步通知为准） |

### 4.5 内网穿透注意

- 沙箱回调也要求公网可达地址；本地联调用 natapp/frp 映射（见《部署手册》§6）。
- 沙箱回调存在延迟，联调时预留等待时间；配合掉单补偿任务验证。

## 5. 快递鸟（物流轨迹）

### 5.1 前置准备

| 项 | 说明 |
|----|------|
| 商户 ID（EBusinessID） | 快递鸟官网注册获取 |
| API key | 签名密钥 |
| 请求类型 | 即时查询 `1002` / 物流跟踪（订阅）`1008` |
| 回调地址 | 物流轨迹推送 `https://<域名>/api/v1/logistics/callback`（需提交白名单） |

### 5.2 对接流程

```
发货（ERP 填单号）→ 物流记录创建（PENDING）
  → 订阅/即时查询快递鸟（按 trackingNo + companyCode）
  → 轨迹返回 → 入库 logistics.traces + 状态更新
  → 推送回调更新轨迹 / 定时轮询补偿（30 分钟）
  → 签收（SIGNED）→ 自动确认收货 → 订单 DEAL_DONE
```

### 5.3 请求与签名约定

- 请求参数 JSON + `RequestData`（URL 编码）+ `EBusinessID` + `DataSign`。
- `DataSign` = Base64(MD5(RequestData + ApiKey))，UTF-8。
- 响应 `Success=true/false`，`State` 为轨迹状态码（3 签收 / 2 派送中 / 1 运输中 / 0 在途等）。

### 5.4 配置项

| 配置 | 说明 |
|------|------|
| `kdniao.ebusiness-id` | 商户 ID |
| `kdniao.api-key` | API key |
| `kdniao.req-url` | 即时查询/订阅接口地址 |
| `kdniao.callback-url` | 轨迹推送回调地址 |

### 5.5 实现要点

- 快递公司编码（SF/YTO/ZTO…）需维护映射（ERP 发货时选择）。
- 回调需校验签名（`DataSign`）后再更新轨迹。
- 轨迹只增量追加；状态变更（尤其签收）触发订单状态机流转（幂等）。

## 6. 配置集中管理约定

- 所有第三方配置统一放 Nacos（`unimarket-dev.yml` / `unimarket-prod.yml`），按 `wechat.*`、`wxpay.*`、`alipay.*`、`kdniao.*` 分组。
- 敏感项（secret/私钥/key）标注 `-secret` 后缀，生产用环境变量/密钥管理注入，**禁止提交仓库**（.gitignore 已排除 `*.local.properties`）。
- 回调地址统一基于 `pay.callback-base-url` / `kdn.callback-base-url` 拼装，不散落硬编码。

## 7. 联调检查清单

### 微信

- [ ] 公众号后台：网页授权域名、JS 安全域名、回调地址已配置
- [ ] access_token 缓存与刷新正常（无频繁 401）
- [ ] 扫码 → 轮询 → 登录闭环通过（内网穿透地址可访问）
- [ ] 同一 openId 重复登录幂等

### 支付（微信/支付宝）

- [ ] 沙箱/测试号下单成功返回支付链接/表单
- [ ] 异步回调验签通过（篡改报文被拒）
- [ ] 回调幂等（重复通知不重复处理）
- [ ] 掉单补偿：手动断回调后 2 分钟内自动补单成功
- [ ] 金额核对：回调金额与支付单一致

### 快递鸟

- [ ] 查询/订阅返回正确轨迹
- [ ] 回调推送验签通过并更新轨迹
- [ ] 签收后订单自动转 DEAL_DONE
