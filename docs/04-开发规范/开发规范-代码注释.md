## 1. 总体原则

| 原则 | 说明 |
|------|------|
| 代码自解释 | 优先用清晰的命名表达意图，注释不重复代码内容 |
| 注释"为什么" | 注释重点说明：为什么这样写、边界条件、业务规则来源 |
| 宁缺毋滥 | 一行废话注释比没有注释更糟 |
| 随代码维护 | 改代码必须同步改注释，禁止注释与代码不一致 |
| 不注释掉代码 | 删除的代码进 Git 历史，不留在注释里 |

**好注释标准**：删掉注释后，读者无法轻易推理出该信息 —— 才值得写。

## 2. 注释类型与使用场景

| 类型 | 语法 | 使用场景 |
|------|------|----------|
| 类/接口注释 | `/** ... */`（Javadoc） | 所有公开类、接口、枚举 |
| 方法注释 | `/** ... */`（Javadoc） | 所有公开方法；复杂私有方法 |
| 字段注释 | `/** ... */` 或行尾 `//` | 字段含义、单位、枚举值说明 |
| 行内注释 | `//` | 解释关键逻辑、边界条件、坑点 |
| 块注释 | `/* ... */` | 大段说明（很少用，优先拆分方法） |
| TODO/FIXME | `// TODO: ...` | 待办事项，须带日期/责任人 |

## 3. Javadoc 规范

### 3.1 类注释

每个公开类/接口必须写，说明**职责**（这个类负责什么），可选说明使用方式。

```java
/**
 * 订单聚合根
 * 负责订单创建、状态流转与金额计算；下单事务内完成锁券、冻结积分与库存扣减。
 */
public class OrderAggregate {
```

### 3.2 枚举注释

枚举值必须说明含义，这是最常见的注释缺失点。

```java
/**
 * 订单状态
 */
public enum OrderStatus {
    CREATE("已创建"),
    PAY_WAIT("待支付"),
    PAY_SUCCESS("支付成功"),
    DEAL_DONE("交易完成"),
    CLOSE("已关闭"),
    REFUND("已退款");

    private final String desc;

    OrderStatus(String desc) {
        this.desc = desc;
    }
}
```

### 3.3 方法注释

- 公开方法必须写 Javadoc：`@param`、`@return`、`@throws`。
- 一句话说明方法做什么（动词开头）。
- 业务规则复杂的，在注释中说明规则来源（如"按 SRS §11.5 互斥矩阵"）。

```java
/**
 * 计算最优优惠券组合
 * <p>先按满足门槛的最大面额满减券，再取折扣最低且上限最高的折扣券；
 * 实现为贪心策略，后续可升级为组合遍历（见 ADR-07）。</p>
 *
 * @param cart        购物车（含选中 SKU 与金额）
 * @param userCoupons 用户可用券列表
 * @return 最优券组合；无可用券返回 null
 * @throws IllegalArgumentException cart 为空或未选中任何商品
 */
public CouponCombination calculateBestCoupon(Cart cart, List<UserCoupon> userCoupons) {
```

### 3.4 常量注释

```java
/** 支付回调验签公钥 */
private static final String ALIPAY_PUBLIC_KEY = "...";

/** 订单超时时间（分钟），超时自动关单 */
private static final int ORDER_TIMEOUT_MINUTES = 30;
```

## 4. 行内注释规范

- 用于解释**不直观**的逻辑：位运算、锁顺序、补偿机制、边界判断。
- 禁止给显而易见的代码加注释（`i++ // i 加一`）。

```java
// 幂等：同 ticket 每 2 秒允许 1 次轮询（微信扫码登录）
if (!rateLimiter.tryAcquire(ticket)) {
    throw new BizException(ErrorCode.TOO_MANY_REQUESTS);
}

// 斐波那契散列：0x61c88647 为黄金分割比的无符号整型表示，均匀映射到 128 槽位
int idx = (int) ((randVal * 0x61c88647L) & (rateTuple.length - 1));
```

**坑点/警告注释**（防止后人踩坑）：

```java
// 注意：这里必须先锁券再扣库存，顺序颠倒会导致并发下死锁
```

## 5. 业务/领域注释规范

| 场景 | 要求 | 示例 |
|------|------|------|
| 状态机 | 注释状态流转条件 | `// 仅 CREATE 且未支付可流转到 PAY_WAIT` |
| 金额计算 | 注明计算顺序与精度 | `// 商品金额 - 优惠券 - 积分抵扣 = 实付金额；金额一律 BigDecimal` |
| 并发控制 | 注明锁/幂等机制 | `// Redis INCR 扣减 + DB 行锁兜底 + 定时对账（三层库存保障）` |
| 最终一致性 | 注明补偿入口 | `// 事务提交后发 MQ；失败由 XXL-Job 扫描 mq_task 补偿` |
| 第三方对接 | 注明厂商限制 | `// 支付宝回调必须返回 success 字符串，否则将重试` |
| 规则/配置 | 注明配置来源 | `// 返利规则来自 daily_behavior_rebate 表配置` |

## 6. 注释语言约定

- 本项目注释统一使用**中文**（团队语言一致），代码标识符用英文。
- 中文注释使用规范标点，句末加句号。
- 禁止中英混杂、拼音缩写（如 `// jg` 表示结果）。
- Javadoc 标签（`@param` 等）用英文标签名，描述用中文。

```java
/**
 * 查询用户积分账户
 *
 * @param userId 用户ID
 * @return 积分账户（含累计/可用/冻结余额）
 */
```

## 7. 禁止事项

| 禁止 | 说明 | 正确做法 |
|------|------|----------|
| 注释掉的死代码 | 留在注释里的旧代码是噪音 | 直接删除，Git 历史可追溯 |
| 废话注释 | `// 遍历列表` 等重复代码的注释 | 删除 |
| 注释与代码不符 | 改代码不改注释 | 同步修改 |
| 注释里写密钥/密码 | 安全红线 | 绝不写入代码与注释 |
| 注释夹带个人吐槽/时间戳 | 无业务价值 | 删除 |
| 每行都注释 | 可读性反而下降 | 按需注释关键点 |
| 用注释代替命名 | `// 状态 1=正常` 而字段叫 `a` | 重命名：`status = NORMAL` |

## 8. 检查清单

提交代码前检查：

- [ ] 新增公开类/接口/枚举有 Javadoc
- [ ] 新增公开方法有 Javadoc（含 @param/@return/@throws）
- [ ] 枚举值、常量含义已注释
- [ ] 业务规则、状态流转、并发/补偿机制有注释
- [ ] 无死代码注释、无废话注释
- [ ] 无注释与代码不一致
- [ ] 无密钥/密码出现在代码与注释
- [ ] 注释语言统一中文，标识符英文
