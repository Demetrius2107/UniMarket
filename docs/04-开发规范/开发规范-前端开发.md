## 1. 总体原则

| 原则 | 说明 |
|------|------|
| 后端为准 | 数据以接口契约为准，前端不做业务规则强校验（防篡改） |
| 组件化 | 页面由组件拼装，公共能力抽象为通用组件 |
| 状态可控 | 全局状态最小化，组件状态就近存放 |
| 响应式 | 兼容微信内置浏览器与移动端 |
| 可维护 | 命名规范、目录清晰、TypeScript 优先（类型即文档） |

**说明**：本文给出通用规范；具体框架（React/Vue）差异在对应小节标注。

## 2. 技术栈与工程结构

| 层 | 推荐 | 说明 |
|----|------|------|
| 框架 | React 18 + TypeScript ／ Vue3 + TypeScript | TS 优先，接口类型安全 |
| UI | Ant Design Pro ／ Element Plus | ERP 表格/表单效率高 |
| 状态 | Redux Toolkit ／ Pinia | 全局状态（用户/购物车/消息未读） |
| 路由 | React Router ／ Vue Router | 懒加载页面 |
| 请求 | Axios | 统一封装（见 §8） |
| 构建 | Vite（推荐）／ Webpack | 构建产物 dist/ |
| 样式 | Less/Sass 或 CSS Modules | 见 §9 |

**工程结构（建议）**：

```
uni-market-front/
├── src/
│   ├── api/          # 接口定义与类型（按模块分文件）
│   ├── assets/       # 静态资源
│   ├── components/   # 通用组件
│   ├── layouts/      # 布局（首页/登录/ERP 框架）
│   ├── pages/        # 页面（C 端 / erp/ 后台）
│   ├── router/       # 路由与守卫
│   ├── store/        # 全局状态
│   ├── utils/        # 工具（请求/格式化/脱敏展示）
│   ├── styles/       # 全局样式与变量
│   └── types/        # 全局类型
├── .env.development  # 开发环境变量（API 代理）
└── .env.production   # 生产环境变量
```

## 3. 目录结构规范

| 目录 | 内容 | 约定 |
|------|------|------|
| `api/` | 接口封装 | 按模块分文件（`user.ts`/`order.ts`），函数命名 `getUserInfo`/`createOrder` |
| `components/` | 通用组件 | 按业务域建子目录；通用型（表格/弹窗）放根级 |
| `pages/` | 页面 | 一个路由一个目录；页面级组件放页面目录内 |
| `utils/` | 工具函数 | 纯函数优先，无副作用 |
| `store/` | 状态 | 按域建 module（user/cart/message） |

**约束**：
- 页面目录内禁止放跨页面复用的组件（提升到 components）。
- 接口调用统一走 `api/`，禁止在组件内直接拼 axios。
- 类型定义：接口出入参类型与 `api/` 同文件定义或 `types/` 统一维护。

## 4. 命名与代码风格

| 类型 | 规范 | 示例 |
|------|------|------|
| 组件/类 | PascalCase | `OrderList`、`CouponCard` |
| 变量/函数 | camelCase | `getOrderList`、`payAmount` |
| 常量 | 全大写下划线 | `PAGE_SIZE`、`PAY_CHANNELS` |
| 文件 | 组件 PascalCase，非组件 kebab-case | `OrderList.tsx`、`request.ts` |
| 目录 | kebab-case | `order-list/` |
| 接口类型 | `I` 前缀或 `DTO` 后缀（与后端对应） | `OrderCreateDTO`、`IUserInfo` |
| 布尔 | 前缀 is/has/can | `isLoading`、`hasCoupon` |

**代码风格**：
- TypeScript 严格模式；禁止 `any` 泛滥（确需用 `unknown` + 类型收窄）。
- 函数组件 + Hooks（React）；Composition API（Vue3）。
- 组件单一职责，单文件建议 ≤ 300 行，超长拆分。
- 事件处理命名 `on<动词>`（`onSubmit`），回调 props 命名 `onXxx`。

## 5. 组件规范

| 规则 | 说明 |
|------|------|
| 通用组件化 | 表格、分页、弹窗、表单、金额展示等抽象为通用组件 |
| Props 设计 | props 尽量扁平；对象类型定义接口，不传散装参数 |
| 受控组件 | 表单/输入受控（value + onChange），避免非受控混用 |
| 展示分离 | 业务组件与纯展示组件分离（数据获取在页面/容器层） |
| 注释 | 复杂组件写 JSDoc：用途、props、示例 |
| 禁止 | 组件内直接操作 DOM 全局（用框架受控方式） |

**金额展示组件约定**：统一 `Price` 组件（BigDecimal 字符串 → 分位展示 `¥xx.xx`），禁止散落格式化逻辑。

## 6. 状态管理与路由

### 6.1 状态管理

| 状态 | 存放位置 | 说明 |
|------|----------|------|
| 用户信息/Token | 全局 store + 本地持久化 | 登录后写入，退出清空 |
| 购物车 | 全局 store（后端数据为准） | 加购/删除/选中同步调接口后更新 |
| 消息未读数 | 全局 store | 轮询/事件刷新 |
| 页面局部状态 | 组件内 state | 如列表 loading/筛选条件 |

**约定**：全局状态只放"多页面共享"数据；接口返回数据不重复存 store（页面直接使用）。

### 6.2 路由与守卫

- 路由懒加载（代码分割）。
- 登录守卫：未登录访问受保护路由 → 跳登录页（或触发扫码登录）。
- 角色守卫：ERP 路由校验运营角色。
- 404 兜底页；接口 401 统一跳登录。

## 7. 接口对接规范

### 7.1 基础约定（对齐《接口开发规范》）

- 基础路径：`/api/v1/`（代理到后端，避免跨域）。
- 请求头：`Authorization: Bearer <token>`；`Content-Type: application/json`。
- 参数：GET 用 query，POST/PUT 用 body（小驼峰）。
- 金额：字符串接收展示，不参与前端浮点计算（精度由后端保证）。

### 7.2 接口定义示例

```ts
// src/api/order.ts
import request from '@/utils/request';

export interface OrderCreateDTO {
  skuIds: string[];
  addressId: string;
  couponId?: string;   // 可选券
  creditAmount?: string; // 积分抵扣（金额字符串）
}

export interface OrderVO {
  orderId: string;
  payAmount: string;   // 金额字符串，避免精度问题
  status: string;
}

export function createOrder(data: OrderCreateDTO) {
  return request.post<OrderVO>('/order/create', data);
}
```

## 8. 请求与响应处理

### 8.1 统一请求封装（Axios 拦截器）

```ts
// utils/request.ts
const service = axios.create({ baseURL: '/api/v1', timeout: 10000 });

// 请求拦截：自动带 Token
service.interceptors.request.use((config) => {
  const token = getToken();
  if (token) config.headers.Authorization = `Bearer ${token}`;
  return config;
});

// 响应拦截：统一解包 Response<T> 与错误提示
service.interceptors.response.use(
  (res) => {
    const { code, message, data } = res.data;
    if (code === 200) return data;
    // 401 → 跳登录；429 → 提示稍后再试；其他 → message.error(message)
    handleBizError(code, message);
    return Promise.reject(new Error(message));
  },
  (err) => {
    // 网络/超时/5xx 统一处理
    handleHttpError(err);
    return Promise.reject(err);
  }
);
```

### 8.2 处理约定

| code | 前端行为 |
|------|----------|
| 200 | 正常返回 data |
| 401 | 清除登录态，跳登录页 |
| 403 | 提示无权限 |
| 429 | 提示"操作过于频繁，请稍后再试" |
| 业务错误 | 用后端 message 提示（toast） |
| 网络/5xx | 统一错误提示 + 埋点 |

### 8.3 并发与竞态

- 列表查询竞态：请求序列号/AbortController 取消过期请求。
- 提交防重复：按钮 loading 态 + 后端幂等兜底。
- 轮询（登录/消息未读）：组件卸载时清理定时器。

## 9. 样式规范

| 规则 | 说明 |
|------|------|
| 方案 | CSS Modules / Scoped 样式，避免全局类名污染 |
| 变量 | 全局样式变量（主色/间距/字号）集中定义 |
| 单位 | 移动端 rem/vw 适配；PC 用 px |
| 布局 | 优先 Flex/Grid，少用绝对定位 |
| 组件库 | 基于 AntD/Element 主题定制，不重复造轮子 |
| 图片 | 懒加载；图标用图标库（iconfont/svg） |

**约定**：样式不写 `!important`（除非覆盖第三方组件且注释原因）；类名语义化（`order-card`）。

## 10. 构建与部署

| 项 | 约定 |
|----|------|
| 构建 | `npm run build` → `dist/`；TypeScript 编译检查通过 |
| 环境变量 | `.env.development`（代理 `/api` → 本地 8091）/ `.env.production`（API 域名） |
| 代码质量 | ESLint + Prettier 统一（提交前 `lint` 通过） |
| 部署 | dist/ 放 Nginx 静态目录，`/api/` 反向代理到后端（见《部署手册》§4.5） |
| 版本 | 每次发布打 tag，与后端版本关联记录 |
| 性能 | 首屏优化：路由懒加载、图片懒加载、依赖按需引入 |
