## 1. 总体原则

| 原则 | 说明 |
|------|------|
| RESTful 语义 | 以资源为中心，用 HTTP 方法表达操作语义 |
| 接口即契约 | 接口一旦发布，字段只增不改；变更需版本管理 |
| 面向 DTO | 接口出入参使用 DTO，禁止直接暴露领域对象/PO |
| 一致性 | 命名、响应结构、错误码全系统统一 |
| 安全默认 | 所有写操作必须鉴权；读接口按需鉴权 |
| 幂等优先 | 下单、支付、领券等关键写接口必须幂等 |

## 2. 接口路径规范

### 2.1 基础规则

- 统一前缀：`/api/v1/`，版本号变更时递增（`v2`）。
- 资源命名：**小写 + 复数名词**，多词用连字符 `-`。
  - ✅ `/api/v1/user/addresses`、`/api/v1/order/list`、`/api/v1/coupon/templates`
  - ❌ `/api/v1/UserInfo`、`/api/v1/getOrderList`（动词前缀）
- 层级关系：`资源/子资源`，最多两级。
  - ✅ `/api/v1/order/{orderId}/items`
- 操作型接口：非资源操作用"动作后缀"，置于路径尾部。
  - ✅ `/api/v1/raffle/draw`、`/api/v1/order/preview`、`/api/v1/order/cancel`
  - ❌ `/api/v1/drawRaffle`、`/api/v1/cancelOrder`
- 查询参数：小驼峰，如 `minPrice`、`categoryId`。

### 2.2 模块路径约定（本系统）

| 模块 | 前缀 | 示例 |
|------|------|------|
| 用户 | `/user/` | `/user/weixin_qrcode_ticket` |
| 商品 | `/product/` | `/product/detail` |
| 购物车 | `/cart/` | `/cart/add` |
| 订单 | `/order/` | `/order/create` |
| 支付回调 | `/order/` | `/order/alipay_notify` |
| 优惠券 | `/coupon/` | `/coupon/calculate` |
| 售后 | `/aftersale/` | `/aftersale/apply` |
| 物流 | `/logistics/` | `/logistics/tracking` |
| 首页 | `/home/` | `/home/banners` |
| 消息 | `/message/` | `/message/unread_count` |
| 抽奖 | `/raffle/` | `/raffle/draw` |
| 拼团 | `/groupbuy/` | `/groupbuy/lock_order` |
| 积分 | `/credit/` | `/credit/account` |

## 3. HTTP 方法与语义

| 方法 | 语义 | 幂等 | 使用场景 | 示例 |
|------|------|------|----------|------|
| GET | 查询 | ✅ | 无副作用查询 | `/product/detail?productId=xxx` |
| POST | 创建/动作 | ❌（需自行保证） | 创建资源、非资源操作 | `/order/create`、`/raffle/draw` |
| PUT | 全量更新 | ✅ | 整体替换/状态流转 | `/user/address` |
| PATCH | 部分更新 | ✅ | 部分字段更新 | 状态变更 |
| DELETE | 删除 | ✅ | 删除资源 | `/cart/remove/{skuId}` |

> 注意：POST 天然非幂等，凡可能重复执行的 POST 接口必须在服务端做幂等处理（见第 9 节）。

## 4. 请求规范

### 4.1 请求体

- 请求体 JSON，字段命名小驼峰。
- 必填字段必须做参数校验（Bean Validation `@NotNull`/`@NotBlank`/`@Size` 等）。
- 时间统一格式 `yyyy-MM-dd HH:mm:ss`（或 ISO-8601），前后端约定一致。
- 金额统一为 `BigDecimal`，单位**元**，禁止用浮点。

### 4.2 请求头

| Header | 必填 | 说明 |
|--------|------|------|
| `Authorization` | 写接口必填 | `Bearer <JWT Token>` |
| `Content-Type` | POST/PUT 必填 | `application/json;charset=UTF-8` |
| `X-Request-Id` | 建议 | 链路追踪/幂等辅助 ID |
| `X-Device-Id` | 游客场景 | 未登录加购等场景的设备标识 |

### 4.3 参数校验失败返回

统一返回业务码 `400`（见错误码表），消息给出具体字段错误。

## 5. 统一响应结构

所有接口（含异常）返回统一结构：

```json
{
  "code": 200,
  "message": "success",
  "data": { },
  "traceId": "8f3a9c2e..."
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| code | int | 业务码，200 成功，非 200 失败（见错误码表） |
| message | string | 人类可读提示，用于前端 toast |
| data | object | 业务数据；无数据时返回 `null` 或空对象 |
| traceId | string | 链路追踪 ID，排障关键 |

**响应体封装类（约定）**：

```java
public class Response<T> {
    private int code;
    private String message;
    private T data;
    private String traceId;
    // 静态工厂：Response.success(data) / Response.failure(code, message)
}
```

**禁止**：
- 直接返回裸对象/裸 List（无法承载错误信息）。
- 返回 `data` 为 `null` 却用 200 表示"失败"（必须用非 200 code）。

## 6. 错误码规范

### 6.1 错误码分段

| 区间 | 含义 | 说明 |
|------|------|------|
| 200 | 成功 | — |
| 400~499 | 客户端错误 | 参数、鉴权、业务校验失败 |
| 500~599 | 服务端错误 | 系统异常、第三方异常 |
| 10000+ | 业务错误 | 各模块细分 |

### 6.2 通用错误码

| code | 含义 | 使用场景 |
|------|------|----------|
| 200 | 成功 | 所有成功响应 |
| 400 | 参数错误 | 参数缺失/格式错误 |
| 401 | 未认证 | Token 缺失/过期/无效 |
| 403 | 无权限 | 越权访问/黑名单拒绝 |
| 404 | 资源不存在 | 查询对象不存在 |
| 409 | 冲突 | 幂等冲突/重复操作 |
| 429 | 请求过于频繁 | 限流触发 |
| 500 | 系统异常 | 未捕获异常兜底 |

### 6.3 业务错误码示例（本系统）

| code | 含义 |
|------|------|
| 10001 | 库存不足 |
| 10002 | 商品已下架 |
| 10003 | 活动未开始或已结束 |
| 10004 | 抽奖次数不足 |
| 10005 | 拼团已满/已失败 |
| 10006 | 优惠券不可用/已过期 |
| 10007 | 积分余额不足 |
| 20001 | 支付回调验签失败 |
| 20002 | 支付单不存在或状态非法 |

> 业务错误码维护在 `types/exception/ErrorCode.java` 枚举中，禁止散落字符串。

## 7. 分页规范

统一分页请求/响应：

**请求参数**：`page`（从 1 开始）、`size`（默认 10，最大 100）。

**响应结构**：

```json
{
  "code": 200,
  "data": {
    "total": 1024,
    "page": 1,
    "size": 10,
    "list": [ ]
  }
}
```

**约定**：
- 分页排序参数 `sort` 取值白名单化（如 `price_asc`、`price_desc`、`sales`），禁止拼接任意字段。
- 使用 MyBatis-Plus `Page` 或等价封装，禁止手写 `LIMIT offset` 造成注入。

## 8. 鉴权规范

- 登录接口发放 JWT Token；Token 中携带 `userId`、`openId`、过期时间。
- 拦截器统一校验：从 `Authorization: Bearer <token>` 解析，失败返回 401。
- Controller 通过 `@RequestAttribute("userId")`（或 `UserContext`）获取当前用户，**禁止**前端传 userId 作为可信来源。
- 越权校验：涉及他人资源（订单、优惠券等）的查询必须校验 `userId` 归属，返回 403。
- ERP 后台接口额外校验运营角色（`role`）。

## 9. 幂等规范

| 场景 | 幂等方案 |
|------|----------|
| 支付回调 | 支付单号唯一索引 + 状态机校验（已成功直接返回 SUCCESS） |
| 创建订单 | 前端 `bizId`（防重键）唯一约束 |
| 领券 | `user_id + template_id` 唯一约束 |
| 签到 | `user_id + 日期` 唯一约束 |
| 积分交易 | `out_biz_no` 唯一索引 |
| 拼团参团 | `biz_id = activityId_userId_count` 唯一索引 |

**实现要点**：数据库唯一索引兜底 + 应用层先查后插（减少冲突），唯一约束冲突时返回"已处理"而非报错。

## 10. 安全规范

- **SQL 注入**：禁止字符串拼接 SQL，全部使用 MyBatis `#{}` 参数绑定；动态排序字段白名单。
- **XSS**：前端输出转义；接口对回显字段（商品名、评论等）做富文本清洗。
- **敏感信息**：响应禁止返回密钥、Token 原文、他人手机号明文；日志脱敏（手机号 `138****1234`）。
- **越权**：所有资源访问做归属校验（见第 8 节）。
- **限流**：登录轮询、抽奖、下单等热点接口加限流（Guava RateLimiter/Sentinel），超限返回 429。
- **验签**：支付回调必须验签，验签失败拒绝处理并告警。
- **上传**：文件上传限制类型/大小，重命名存储，禁止直接使用用户文件名。

## 11. 文档与注释要求

- 接口必须使用 Swagger 注解：`@Tag`（类）、`@Operation`（方法，写明说明与示例）、`@Parameter`（复杂参数）。
- Controller 方法必须写方法注释（Javadoc），说明业务含义、异常情况。
- DTO 字段必须注释含义与单位（金额/时间）。
- 非业务字段（如 `page`）可省略示例，业务字段必须有 `example`。

```java
@Operation(summary = "创建订单", description = "支持购物车批量下单、优惠券、积分抵扣")
@PostMapping("/create")
public Response<OrderCreateVO> createOrder(@Valid @RequestBody OrderCreateDTO dto) {
    // ...
}
```

## 12. 接口评审清单

提交/联调前逐项检查：

- [ ] 路径符合 RESTful 命名规范（名词复数、动作后缀）
- [ ] 响应为统一 `Response<T>` 结构
- [ ] 错误码使用 `ErrorCode` 枚举，未散落魔法数字
- [ ] 写接口已鉴权；资源访问有归属校验
- [ ] 关键写接口有幂等设计（唯一索引兜底）
- [ ] 分页参数白名单排序，无 SQL 注入风险
- [ ] 敏感字段已脱敏，日志无明文
- [ ] Swagger 注解与 Javadoc 完整
- [ ] 金额字段 BigDecimal，时间格式统一
- [ ] 有对应单元测试（service 层）覆盖核心分支
