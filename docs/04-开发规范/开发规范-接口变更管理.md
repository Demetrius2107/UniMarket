# 接口变更管理规范 — UniMarket

> 适用于 UniMarket 统一商城前台的接口版本化、兼容性保证、废弃与变更评审管理。
> 目标：接口作为对外契约，变更不破坏既有调用方，变更可追溯可回滚。

## 1. 总体原则

| 原则 | 说明 |
|------|------|
| 接口即契约 | 已发布接口对调用方承诺稳定，变更需谨慎 |
| 向后兼容 | 变更优先做到旧调用方无感知 |
| 只增不删 | 字段只增不改语义；删除走废弃流程 |
| 变更可回溯 | 每次变更有记录（接口清单 + changelog） |
| 评审先行 | 破坏性变更必须评审 + 通知调用方 |

**适用对象**：`/api/v1/**` 对外接口、第三方回调接口（支付宝/微信/快递鸟）、MQ 消息契约。

## 2. 版本化策略

### 2.1 路径版本

- 基础路径含版本：`/api/v1/`、`/api/v2/`。
- 破坏性变更 → 新版本路径（`v2`），旧版本并行运行一个过渡期。

### 2.2 版本演进规则

| 版本 | 说明 |
|------|------|
| v1 | 当前稳定版本，字段只增不改 |
| v2 | 破坏性变更时新增，过渡期后 v1 废弃下线 |

**约定**：
- 小版本（新增字段/接口）不升路径版本，直接加字段。
- 大版本（改语义/删字段/改协议）升路径版本。
- 同一资源多版本并存时，代码层面 DTO 分离（`OrderCreateDTOV1` / `V2`），避免互相污染。

## 3. 兼容性规则

### 3.1 兼容（允许直接发布）

| 变更 | 示例 |
|------|------|
| 新增接口 | 新增 `/order/preview` |
| 新增可选字段 | 请求体加 `couponId`（可空）；响应加 `discountAmount` |
| 新增响应字段 | 响应 `data` 增加字段（不影响旧解析） |
| 新增枚举值 | `order_type` 增加 `CREDIT`（旧值不变） |
| 参数默认值 | 新增可选参数带默认值，行为一致 |

### 3.2 不兼容（必须升版本/评审）

| 变更 | 示例 |
|------|------|
| 删除字段/接口 | 删除 `couponId` 参数 |
| 修改字段语义 | `status` 值含义改变、金额单位改变 |
| 修改必填性 | 可选变必填 |
| 修改错误码语义 | 同 code 含义变化 |
| 修改协议/鉴权方式 | 响应结构变化、Token 校验规则变化 |
| 修改回调格式 | 支付回调报文结构调整 |

## 4. 变更类型分级

| 级别 | 定义 | 处理 |
|------|------|------|
| A 兼容变更 | 新增字段/接口，不影响旧调用 | 直接发布，更新接口清单 |
| B 有风险变更 | 新增参数但默认值行为可能变化 | 评审 + 回归测试 + 通知调用方 |
| C 破坏性变更 | 语义/结构/必填变化 | 升版本路径 + 评审 + 过渡期 + 调用方迁移 |

**判定方法**：变更后，旧请求（不携带任何新参数）的行为是否与变更前完全一致？一致 → A/B；不一致 → C。

---

## 5. 变更流程

```
1. 提出变更：说明背景、影响面（哪些调用方/模块）
2. 分级：按 §4 判定 A/B/C
3. 评审：
   - A：直接实现，更新接口清单
   - B：评审 + 补充回归用例
   - C：设计 v2 方案 + 过渡期 + 迁移计划，评审通过后实施
4. 实现与测试：兼容性用例（旧请求行为不变）纳入测试
5. 发布：A/B 随版本发布；C 需通知调用方并按迁移计划推进
6. 记录：更新接口清单 changelog（日期/变更/影响/版本）
```

---

## 6. 废弃（Deprecation）流程

```
1. 标记废弃：接口保留但注解/文档标记 @Deprecated（保留至少 1 个大版本周期）
2. 通知调用方：废弃说明 + 替代接口 + 下线时间
3. 观察期：监控废弃接口调用量归零
4. 下线：确认无调用后删除，记录 changelog
```

**约定**：
- 废弃接口仍保持行为稳定，不顺手改逻辑。
- 禁止跳过观察期直接删除（调用方未迁移会直接故障）。

## 7. 接口清单与契约管理

- 接口清单维护在《设计文档-SDS》§8（API 接口设计），变更同步更新。
- 新增/变更接口登记 `docs/01-需求/需求追溯矩阵.csv` 对应需求行。
- 接口契约以 Swagger 注解为准（`@Operation`/`@Schema`），变更必须同步注释。

## 8. 检查清单

- [ ] 变更前判定类型（A/B/C），破坏性变更走 v2 方案
- [ ] 兼容性：旧请求行为不变（有回归用例验证）
- [ ] 新增字段可空/带默认值，不改变既有语义
- [ ] 不兼容变更已评审 + 通知调用方 + 确定过渡期
- [ ] 废弃接口已标记 @Deprecated 且有替代方案
- [ ] 接口清单与 Swagger 注释已同步更新
- [ ] 变更已登记 changelog
