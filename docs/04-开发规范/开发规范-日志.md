## 1. 总体原则

| 原则 | 说明 |
|------|------|
| 有迹可循 | 关键业务流程必须有日志（入参摘要、关键节点、结果） |
| 级别准确 | 级别代表问题严重度，禁止滥用 error/info |
| 少而精 | 不打无意义日志；线上禁止 debug |
| 安全合规 | 日志不落敏感信息（密码/Token/完整手机号/密钥） |
| 链路贯穿 | 单次请求所有日志带同一 traceId |

**日志价值排序**：排障 > 审计 > 埋点分析 > 状态展示。

## 2. 日志框架与配置

| 项 | 约定 |
|----|------|
| 框架 | SLF4J + Logback（Spring Boot 默认） |
| 使用 | 一律 `LoggerFactory.getLogger(Class)`；禁止 `System.out` / `System.err` |
| 异步 | 生产开启异步 Appender（AsyncAppender），避免日志阻塞业务 |
| 滚动 | 按天滚动 + 大小限制（如 500MB），保留 30 天 |
| 环境 | dev 可开 DEBUG；test 开 INFO；prod 开 INFO（ERROR 单独文件） |

```xml
<!-- logback-spring.xml 关键点：pattern 必须含 traceId -->
<pattern>%d{yyyy-MM-dd HH:mm:ss.SSS} %-5level [%thread] [%X{traceId}] %logger{40} - %msg%n</pattern>
```

## 3. 日志级别规范

| 级别 | 使用场景 | 示例 |
|------|----------|------|
| TRACE | 调试细节（几乎不用） | 算法中间量（仅本地调试） |
| DEBUG | 开发调试 | 参数明细、分支详情（生产关闭） |
| INFO | 关键业务节点、启动、任务执行 | 下单成功、支付回调处理、定时任务开始/结束 |
| WARN | 可恢复的异常/降级/重试 | 第三方调用失败将重试、库存对账不一致已修正 |
| ERROR | 不可恢复异常/需要人工介入 | 验签失败、MQ 补偿 3 次仍失败、任务执行异常 |

**使用原则**：
- INFO：记录"发生了什么"（业务事件 + 关键 ID），不记录无谓的每行细节。
- ERROR：必须可定位（带 traceId、业务单号、堆栈）。
- **禁止**用 ERROR 打"预期内的业务校验失败"（如库存不足用 WARN 或业务返回，不打 ERROR）。

```java
// INFO：业务关键节点
log.info("order pay success. orderId={}, payAmount={}", orderId, payAmount);

// WARN：可恢复
log.warn("third-party pay query timeout, will retry. outTradeNo={}", outTradeNo, e);

// ERROR：不可恢复
log.error("alipay notify verify failed. notifyBody={}", maskedBody, e);
```

## 4. 日志格式规范

### 4.1 格式

```
时间 [级别] [线程] [traceId] 类名 - 消息
2026-08-10 22:00:00.123 INFO [http-nio-8091-exec-3] [a1b2c3d4] cn.unimarket.service.OrderService - order create success. orderId=O1001
```

### 4.2 消息写法

- 参数化占位 `{}`，禁止字符串拼接（性能 + 可读性）。
  - ✅ `log.info("user login. userId={}", userId)`
  - ❌ `log.info("user login. userId=" + userId)`
- 关键业务必须带业务单号（orderId/outTradeNo/activityId/teamId）。
- 一个日志一句话，禁止大段 JSON 堆叠（结构化字段按需拆分）。

## 5. 日志链路追踪（traceId）

| 项 | 约定 |
|----|------|
| 生成 | 请求入口（网关/Filter）生成 traceId（UUID/雪花），放入 MDC |
| 传递 | 通过 MDC + 请求头（`X-Request-Id`）贯穿 HTTP 调用 |
| 异步 | MQ 消息体带 traceId，消费者取出后 set 回 MDC |
| 定时任务 | 每次执行生成独立 traceId |
| 对外 | 响应体 `traceId` 字段返回（见《接口开发规范》§5） |

```java
// 入口 Filter：MDC 设置 traceId
MDC.put("traceId", request.getHeader("X-Request-Id") != null
    ? request.getHeader("X-Request-Id") : UUID.randomUUID().toString());
// finally 中 MDC.remove("traceId") 防止线程复用污染
```

**目标**：任意一笔订单/一次异常，可按 traceId 在 ELK 检索完整链路。

## 6. 业务日志约定

| 场景 | 必记内容 |
|------|----------|
| 下单 | 入参摘要（skuIds/数量）、订单号、金额、券/积分使用 |
| 支付回调 | 支付单号、验签结果、回调内容（脱敏）、处理结果 |
| 抽奖 | 活动/策略/用户、中奖结果、发奖消息发送结果 |
| 拼团 | 队伍/订单、锁单/成团/退款动作与结果 |
| 定时任务 | 任务名、开始/结束、处理条数、失败明细 |
| 补偿任务 | 补偿消息 ID、重试次数、最终状态 |
| 降级/限流 | 触发点、阈值、降级结果 |

**原则**：日志记录"可复现问题"的最少必要信息，不记录全量请求体（大报文摘要化）。

## 7. 敏感信息脱敏

| 字段 | 脱敏规则 | 示例 |
|------|----------|------|
| 手机号 | 保留前 3 后 4 | `138****1234` |
| 身份证 | 保留前 3 后 4 | `110***********1234` |
| 银行卡 | 保留后 4 | `****1234` |
| 邮箱 | 保留首字符与域名 | `a***@qq.com` |
| Token/密钥/密码 | 禁止输出，打 `***` | `token=***` |
| 支付回调报文 | 签名/敏感字段打码后记录 | `{... "sign":"***"}` |

**统一工具**：`SensitiveUtil.mask(phone)` 等集中实现，禁止各业务自拼脱敏逻辑。

## 8. 禁止事项

| 禁止 | 原因 | 正确做法 |
|------|------|----------|
| `System.out` / `e.printStackTrace()` | 无级别、无格式、不可控 | SLF4J 日志 |
| 日志打密码/Token/密钥 | 严重安全风险 | 打码/不记 |
| 空 catch 无日志 | 吞异常无法排障 | catch 后记录并处理 |
| 循环内打 INFO 日志 | 刷屏 + 性能 | 批量摘要/DEBUG |
| 打全量请求体/响应体 | 大报文 + 敏感泄漏 | 摘要/脱敏 |
| 生产开 DEBUG | 性能与噪音 | 生产 INFO |
| 日志输出 JSON 无格式化 | 不可读 | 参数化 + 按字段拆分 |
| 级别滥用（预期失败打 ERROR） | 告警噪音 | 业务失败 WARN/业务码 |

## 9. ELK 采集约定

- 日志输出到文件（`logs/unimarket-app.log`），Filebeat 采集 → Logstash → ES → Kibana。
- 索引按天：`unimarket-{yyyy.MM.dd}`。
- Kibana 检索：优先按 `traceId` 检索单笔链路；按 `logger`/级别/业务单号聚合分析。
- 关键业务（订单/支付）日志字段可加标签（`biz=order`），便于过滤与告警规则。

## 10. 检查清单

- [ ] 全部使用 SLF4J，无 System.out / printStackTrace
- [ ] 日志级别符合 §3（预期失败不打 ERROR）
- [ ] 消息参数化 `{}`，带业务单号
- [ ] 入口设置 traceId，异步/任务链路贯穿
- [ ] 敏感字段已脱敏，无密钥/Token 明文
- [ ] 无空 catch、无循环内 INFO 刷屏
- [ ] 关键业务节点（下单/回调/任务）有日志
- [ ] 日志格式含 traceId，ELK 可检索
