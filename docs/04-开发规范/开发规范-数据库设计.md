## 1. 总体原则

| 原则 | 说明 |
|------|------|
| 命名即语义 | 表名/字段名自解释，见名知义 |
| 范式与冗余平衡 | 核心交易表 3NF；读多场景允许冗余（如订单快照商品名） |
| 索引为查询服务 | 先有查询场景再建索引，禁止无脑全列索引 |
| 金额/状态用数值语义 | 金额 DECIMAL，状态用枚举值/字符串，不玩位运算 |
| 变更可回滚 | DDL 变更走评审，生产变更必须可回滚方案 |

**目标**：表结构稳定、查询高效、数据一致、运维可理解。

## 2. 库表命名规范

### 2.1 库

- 库名小写，下划线分词：`uni_market`（公共库）、`uni_market_01/02`（分库）、`xxl_job`（任务调度库）。
- 单库字符集 `utf8mb4`，排序规则 `utf8mb4_unicode_ci`。

### 2.2 表

- 表名小写 + 下划线，**单数名词**（`order` 而非 `orders`），不超过 3 个词。
- 业务前缀分组：`user_*`（用户）、`order_*`（订单）、`pay_*`（支付）、`activity_*`（活动）、`group_buy_*`（拼团）、`lottery_*`（抽奖）、`credit_*`（积分）、`coupon_*`（优惠券）、`rule_*`（规则）。
- 关联表：`<主表>_<关联表>`，如 `activity_sku`。
- 分表：`<表名>_<三位分片>`，如 `order_000`；分片号补零三位。
- 禁止：中文表名、保留字（`order` 需注意在部分方言是保留字，本项目约定可用，但加前缀更稳，如 `t_order`——本系统统一用 `order` 时注意 SQL 中避免歧义）、无意义缩写（`tb1`）。

### 2.3 表注释

每张表必须有 `COMMENT` 说明用途；字段必须有 `COMMENT` 说明含义与单位（金额/状态枚举值）。

## 3. 字段设计规范

| 规则 | 说明 | 示例 |
|------|------|------|
| 命名 | 小写 + 下划线，见名知义 | `pay_amount`、`available_amount` |
| 金额 | `DECIMAL(10,2)`（特大金额 DECIMAL(12,2)）；禁止 float/double | `DECIMAL(10,2) NOT NULL DEFAULT 0.00` |
| 整数 | `INT` / `BIGINT`（ID、计数、数量）；计数用 `INT UNSIGNED` 可选 | `quantity INT NOT NULL DEFAULT 1` |
| 字符串 | 长度明确 `VARCHAR(n)`；大文本 `TEXT`/`MEDIUMTEXT` | 名称 `VARCHAR(128)`，描述 `TEXT` |
| 状态 | 枚举值用 `VARCHAR(16)` + 注释枚举含义，或 `TINYINT` + 注释；禁止裸数字无注释 | `status VARCHAR(16) COMMENT 'CREATE/PAY_WAIT/...'` |
| 时间 | `DATETIME`，禁止字符串时间 | `create_time DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP` |
| 布尔 | `TINYINT(1)` 0/1，字段名用 `is_` 前缀可选 | `is_read TINYINT NOT NULL DEFAULT 0` |
| 唯一标识 | 业务 ID 用 `VARCHAR(32)`（雪花），不用自增主键当业务 ID | `order_id VARCHAR(32)` |
| 外键 | **禁止物理外键**，用逻辑关联 + 索引（分布式/分库场景 FK 无意义） | 仅建索引 |
| 预留字段 | 禁止无意义的 `remark`/`ext` 大杂烩；确有扩展用明确字段或 JSON 列 | — |

**必含字段**（每张表）：

```sql
`id` BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '自增主键',
`create_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
`update_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
PRIMARY KEY (`id`)
```

**逻辑删除**（如需）：`deleted TINYINT NOT NULL DEFAULT 0 COMMENT '0未删/1已删'`，查询统一过滤。

## 4. 索引规范

| 规则 | 说明 |
|------|------|
| 命名 | `idx_<字段>` / `uk_<字段>`（唯一）；如 `idx_user_status`、`uk_order_id` |
| 左前缀 | 联合索引遵守最左前缀原则，把等值列放前面 |
| 覆盖索引 | 高频查询尽量覆盖（select 所需列在索引内），避免回表 |
| 区分度 | 区分度低的列（状态）不单独建索引，与其他列联合 |
| 数量控制 | 单表索引 ≤ 5 个；禁止冗余索引（`idx_a` + `idx_a_b`） |
| 禁止 | 索引上做函数运算/隐式类型转换（`WHERE DATE(create_time)=...`、`WHERE phone=12345` 字符串列传数字） |
| 索引失效排查 | 联合索引跳过前置列、`LIKE '%xx'`、`OR` 连接非索引列 |

```sql
-- 正确：联合索引 idx_user_status(user_id, status)
SELECT * FROM user_coupon WHERE user_id = 'u1' AND status = 'UNUSED';

-- 禁止：函数运算导致索引失效
SELECT * FROM order_000 WHERE DATE(create_time) = '2026-08-10';
```

## 5. 主键与唯一约束

| 规则 | 说明 |
|------|------|
| 主键 | 自增 `BIGINT` 主键（分库分表内局部自增）+ 业务唯一键（`uk_*`） |
| 业务唯一键 | 所有业务可重复风险必须有唯一约束（幂等兜底） |
| 唯一键命名 | `uk_<关键字段>` |

本系统幂等唯一键（对照《接口开发规范》§9）：

| 表 | 唯一约束 |
|----|----------|
| `order` | `uk_order_id` |
| `pay_order` | `uk_pay_id`、`uk_out_trade_no` |
| `user_credit_order` | `uk_order_id`（交易单号）、`out_biz_no` |
| `group_buy_order` | `uk_order_id`、`uk_biz_id(activityId_userId_count)` |
| `user_coupon` | `uk_user_coupon_id` |
| `lottery_order` | `uk_order_id` |
| `user` | `uk_user_id`、`uk_open_id` |

## 6. 事务与锁

| 规则 | 说明 |
|------|------|
| 事务边界 | Service 层 `@Transactional`，只读查询不加事务 |
| 事务粒度 | 事务内禁止 RPC/外部调用/长循环（拉长锁与连接） |
| 隔离级别 | 默认 READ COMMITTED 或 REPEATABLE READ 按需；业务无特殊不显式改 |
| 行锁 | 精确扣减用 `UPDATE ... WHERE ... AND stock > 0`（行锁 + 条件），不用 `SELECT FOR UPDATE` 后更新 |
| 锁顺序 | 多资源加锁必须固定顺序，防死锁（见《Java 编码规范》§5） |
| 大事务 | 单事务操作行数建议 < 1000；批量操作用分批事务（如补偿任务每批 500） |

```sql
-- 精确扣减（行锁 + 条件判断），禁 SELECT FOR UPDATE + 应用层判断
UPDATE strategy_award
SET award_surplus_count = award_surplus_count - 1
WHERE strategy_id = #{strategyId} AND award_id = #{awardId} AND award_surplus_count > 0;
```

## 7. SQL 编写规范

| 规则 | 说明 |
|------|------|
| 禁止 `SELECT *` | 明确列出所需列（含分页、联表） |
| 分页 | 统一 `LIMIT #{offset}, #{size}`（MyBatis 分页插件）；深分页用游标/子查询优化 |
| 联表 | 小表驱动大表；禁止 3 张以上大表无脑 JOIN（可拆分查询或冗余） |
| 参数 | MyBatis 一律 `#{}` 绑定，禁止 `${}` 拼接（排序字段除外，走白名单） |
| 批量 | 批量插入/更新用 `<foreach>` 或批处理，禁止循环单条 SQL |
| 时间比较 | 时间范围用 `>=` / `<` 半开区间（`create_time >= ? AND create_time < ?`），避免 `BETWEEN` 边界歧义 |
| 聚合 | 大表聚合统计走汇总表/ES，禁止实时 COUNT 大表 |

```java
// MyBatis 禁止 ${} 拼接用户输入
// ❌ ORDER BY ${sortField}
// ✅ 白名单映射：sortField 映射到固定列名后拼接
```

## 8. 分库分表约定

| 项 | 约定 |
|----|------|
| 分片键 | 一律 `userId`（哈希路由，见 SDS §10.4）；禁止非分片键全表扫描 |
| 路由 | MyBatis 拦截器统一路由（DBContextHolder），业务不感知 |
| 分布式 ID | 业务 ID 雪花算法（`VARCHAR(32)`），分片内自增主键不对外 |
| 跨分片 | 禁止跨分片 JOIN/事务；跨分片聚合走汇总/应用层合并 |
| 公共数据 | 配置类数据（商品/活动/券模板）放公共库 db00，不分片 |
| 扩容 | 2×4 → 4×8 扩容方案预留（路由算法参数化：dbCount/tbCount 可配） |

## 9. 字符集与时区

- 库/表/字段统一 `utf8mb4`（支持 emoji 与生僻字），排序 `utf8mb4_unicode_ci`。
- 连接串统一 `characterEncoding=utf8&serverTimezone=Asia/Shanghai&useSSL=false`。
- 时间字段统一 `DATETIME`，应用层 `LocalDateTime`，不做时区换算歧义。
- 建表语句落 `docs/sql/`，按环境可重复执行（幂等：`CREATE TABLE IF NOT EXISTS` 或迁移脚本）。

## 10. SQL 评审检查清单

提交/上线前检查：

- [ ] 表/字段命名符合 §2/§3，有 COMMENT
- [ ] 金额 DECIMAL，状态有枚举注释，时间 DATETIME
- [ ] 必含 create_time/update_time/主键；业务唯一键齐备
- [ ] 索引命名 `idx_/uk_`，符合左前缀，无冗余索引
- [ ] 无物理外键、无 `SELECT *`、无 `${}` 拼接
- [ ] 事务边界合理，扣减用行锁条件更新
- [ ] 分库分表路由走统一拦截器，无跨分片操作
- [ ] 字符集 utf8mb4，连接串含 serverTimezone
- [ ] DDL 落 docs/sql/ 且可重复执行
