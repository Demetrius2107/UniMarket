# ADR-03：模块化单体 + Dubbo RPC 假拆分

- **状态**：已接受（Accepted）
- **日期**：2026-08-10
- **关联文档**：《设计文档-SDS》§3/§4、《PRD》附录 C
- **影响范围**：整体架构形态

## 背景

本项目定位是"一个人能完成的完整系统"，但又希望架构具备未来拆分能力。真正微服务化（独立进程、独立部署、分布式事务治理）对单人项目代价过高。

## 决策

采用 **模块化单体**：按 DDD 领域边界划分 Maven 模块（domain/infrastructure/trigger/app），进程内模块化；各领域模块间的接口**预留 Dubbo RPC 边界**（api 模块定义 RPC Service 接口），未来可平滑拆分为独立微服务。

- 启动为单 Spring Boot 应用（uni-market-app）。
- 领域间通过应用层服务/领域事件解耦，不直接跨模块引用实现类。

## 后果

- 正面：开发调试简单、部署运维成本低；接口已按 RPC 契约设计，拆分时改动小。
- 负面：单进程故障域（限流熔断仍可保护）；不是真正独立扩缩容。

## 备选方案

- 真正微服务拆分：独立进程+独立库，但开发/部署/联调成本高，不适合单人 16 周周期。
- 纯单模块：开发快但模块边界模糊，后续拆分困难。

## 演进

流量增长或团队扩张后，按 domain 边界逐个拆出独立服务（复用已预留 RPC 接口）。
