# ADR-05：购物车双层存储（Redis 热 + MySQL 冷）

- **状态**：已接受（Accepted）
- **日期**：2026-08-10
- **关联文档**：《设计文档-SDS》§6.6、《开发规范-RedisKey设计》§5
- **影响范围**：购物车模块

## 背景

购物车是高频读写数据：加购/改数量/勾选要求低延迟；同时购物车数据不能因 Redis 故障而永久丢失。

## 决策

采用**双层存储**：

- **Redis（热数据）**：`cart:{userId}` Hash 结构，TTL 30 天，承担高频读写。
- **MySQL（冷备份）**：`cart_item_000~_003` 分表，定期/异步落库兜底。

辅助约定：
- 未登录加购存 `cart:device:{deviceId}`，登录后 `mergeCart()` 合并。
- 进入购物车页实时校验库存与价格，标记失效商品。

## 后果

- 正面：读写低延迟；Redis 丢失可从 MySQL 恢复；未登录体验完整。
- 负面：双写一致性需保证（异步落库 + 补偿）；Redis 内存占用需监控。

## 备选方案

- 仅 Redis：实现简单但数据可靠性依赖 Redis 持久化，故障有丢失风险。
- 仅 MySQL：数据可靠但高频读写性能差，购物车体验受影响。

## 演进

数据量增长后可仅保留 Redis（购物车作为可重建数据，降级冷备频次）或迁移至其他 KV。
