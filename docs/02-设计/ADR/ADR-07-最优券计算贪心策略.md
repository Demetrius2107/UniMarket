# ADR-07：最优券计算先实现贪心策略

- **状态**：已接受（Accepted）
- **日期**：2026-08-10
- **关联文档**：《设计文档-SDS》§6.7、《需求文档-SRS》BR-01
- **影响范围**：优惠券计算引擎

## 背景

`calculateBestCoupon()` 需要在用户可用券中选出最优组合。组合遍历（多张券叠加）能求全局最优，但复杂度随券数量指数增长，且券叠加规则复杂。

## 决策

第一版实现**贪心策略**：

- 满减券：选择满足门槛的最大面额。
- 折扣券：选择折扣最低且上限最高的。
- 先取最大优惠的单张券（或简单叠加），快速给出可用结果。

后续（数据量/规则复杂度上来后）再优化为**组合遍历**求全局最优。

## 后果

- 正面：实现简单、性能快、规则清晰，Phase 6 可快速交付。
- 负面：多张券组合场景下可能非全局最优（用户优惠略少）。

## 备选方案

- 组合遍历（动态规划/回溯）：全局最优但实现复杂、计算开销大，作为二期优化项。

## 演进

通过 DCC 开关 `coupon.calc-strategy`（greedy/combine）灰度切换两种算法（见《配置规范-Nacos配置清单》§5）。
