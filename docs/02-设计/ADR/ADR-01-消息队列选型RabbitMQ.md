# ADR-01：选择 RabbitMQ 而非 Kafka 作为消息队列

- **状态**：已接受（Accepted）
- **日期**：2026-08-10
- **关联文档**：《设计文档-SDS》§12 ADR-01、《开发规范-MQ与定时任务》
- **影响范围**：全部异步链路（支付回调、发奖、积分、通知）

## 背景

系统存在支付回调、异步发奖、积分调整、成团通知等多种异步解耦场景，需要选择消息中间件。候选：RabbitMQ 与 Kafka。

## 决策

选择 **RabbitMQ 3.12.x** 作为统一消息队列。

理由：
- 对延迟敏感业务（如支付回调）更友好，消息延迟更低。
- Topic/路由更灵活，支持 direct/topic/fanout 多种交换机，适配业务事件模型。
- 管理界面完善，队列积压/死信等运维能力直观。
- 单机部署运维成本低，适合本系统规模。

## 后果

- 正面：支付回调链路延迟低；灵活路由支撑多消费者订阅；运维直观。
- 负面：吞吐量上限低于 Kafka；日志/埋点等海量消息场景需另行评估。

## 备选方案

- Kafka：吞吐高、分区并行强，但延迟相对高、运维复杂；未来日志/埋点量大时可作为**第二条 MQ 线**与 RabbitMQ 并存（保留演进空间）。
