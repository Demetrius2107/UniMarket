# ADR-06：售后逆向流程采用最终一致性（本地消息表 + MQ）

- **状态**：已接受（Accepted）
- **日期**：2026-08-10
- **关联文档**：《设计文档-SDS》§10.6、《开发规范-MQ与定时任务》§6、《需求文档-SRS》BR-26
- **影响范围**：售后退款、退券、退积分链路

## 背景

售后退款涉及跨写操作：原路退款（第三方）、退券（user_coupon 状态）、退积分（积分账户）。强一致分布式事务（2PC/TCC）复杂度高、性能差，对单人项目不划算。

## 决策

采用**最终一致性**：本地消息表（notify_task/mq_task）+ RabbitMQ 异步 + XXL-Job 定时补偿三层保障（SDS §10.6）。

- 业务事务内写本地消息表，事务提交后发 MQ。
- 消费者处理退款/退券/退积分，成功更新消息状态。
- 失败由定时任务补偿重试（最多 3 次），仍失败告警人工介入。

## 后果

- 正面：实现简单可靠；不引入分布式事务中间件；退款链路最终一致。
- 负面：短时间内（补偿窗口内）数据可能不一致（可接受，有补偿兜底）。

## 备选方案

- TCC/2PC 强一致：数据实时一致但实现复杂、性能开销大，对当前规模不划算。
- 同步串行处理：实现简单但第三方退款慢会拖垮主流程，且部分失败难补偿。

## 演进

若未来出现强一致硬性要求（如资金类），可针对单条链路升级为本地事务+对账方案。
