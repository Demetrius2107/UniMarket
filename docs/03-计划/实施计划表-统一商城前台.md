## 3. 阶段明细（12 阶段）

### Phase 1：基础骨架（Week 1-2）

**目标**：搭建项目骨架，跑通最简链路。里程碑：**登录 → 看商品 → 下单 → 选支付方式 → 支付 → 订单完成**。

| # | 任务 | 内容 | 产出 |
|---|------|------|------|
| 1.1 | 环境准备 | Docker Compose 起 MySQL/Redis/RabbitMQ/Nacos；内网穿透工具 | 一键环境脚本 |
| 1.2 | 项目初始化 | Maven 多模块骨架（api/types/domain/infrastructure/trigger/app） | 可启动的空项目 |
| 1.3 | 建库建表 | 全部核心表 DDL（公共库 + 分库分表） | docs/sql 完整 SQL |
| 1.4 | 用户模块 | 微信扫码登录（ticket 机制 + 轮询 + JWT） | 登录 → 鉴权闭环 |
| 1.5 | 商品模块 | 商品 CRUD + 列表查询 + 分类管理 | 建表 + API |
| 1.6 | 订单模块 | 最简下单流程（CREATE → PAY_WAIT → PAY_SUCCESS） | 单表操作，不涉及营销 |
| 1.7 | 支付模块 | 支付宝沙箱 + 微信支付适配；统一收银台；回调验签；掉单补偿 + 超时关单 | 支付渠道抽象接口 |

**验收**：E2E-01/02/03（登录、浏览下单、支付回调）跑通；订单状态机正确；掉单 ≤ 2 分钟自动补偿。

### Phase 2：商品搜索 + 购物车（Week 3）

**目标**：搜索与购物车可用。里程碑：**用户搜索商品 → 加入购物车 → 勾选结算**。

| # | 任务 | 内容 |
|---|------|------|
| 2.1 | ES 商品索引 | Canal 同步 MySQL → ES（可先 SDK 直写简化），建立商品索引 |
| 2.2 | 全文搜索 API | `/product/search` 关键词+分类+价格区间+排序 |
| 2.3 | 搜索建议 | 自动补全 + 热门搜索词 |
| 2.4 | 购物车 Redis 实现 | cart:userId Hash → add/update/remove/select |
| 2.5 | 购物车合并 | deviceId cart → userId cart 登录合并 |
| 2.6 | 购物车校验 | 进购物车页实时校验库存/价格/状态，标记失效 |

**验收**：搜索 P95 < 500ms；数据变更 ≤ 1 分钟生效；失效商品提示且不可下单；登录合并正确。

### Phase 3：营销引擎 — 抽奖（Week 4-5）

**目标**：抽奖全链路。里程碑：**签到/购物得次数 → 抽奖 → 中奖 → 发奖**。

| # | 任务 | 内容 |
|---|------|------|
| 3.1 | 抽奖策略配置 | strategy / strategy_award / award 表 + CRUD |
| 3.2 | 抽奖算法 | 单项概率（斐波那契散列 O(1)）+ 总体概率两种算法 |
| 3.3 | 活动管理 | marketing_activity 表 + 状态机（EDIT→提审→PASS→DOING→CLOSE） |
| 3.4 | 活动参与 | 活动账户扣减（总/日/月）+ Redis 库存管理 |
| 3.5 | 规则引擎 | 决策树实现（黑名单/权重/锁次数/兜底） |
| 3.6 | 奖品发放 | 发奖工厂 + MQ 异步（文字/码/券/实物/积分） |
| 3.7 | MQ 补偿 | 本地消息表 + XXL-Job 定时补偿 |
| 3.8 | 装配预热 | strategy/activity armory 数据预热 |

**验收**：并发下库存不超发；发奖消息最终必达；决策树规则（锁次数/库存/兜底）生效。

### Phase 4：营销引擎 — 拼团（Week 6-7）

**目标**：拼团全链路。里程碑：**开团 → 邀请 → 参团 → 支付 → 成团/超时退款**。

| # | 任务 | 内容 |
|---|------|------|
| 4.1 | 折扣引擎 | 直减/满减/折扣/N 元购 4 种策略（策略模式） |
| 4.2 | 拼团锁单 | 责任链校验 + bizId 防重 + Redis 库存控制 |
| 4.3 | 拼团结算 | 支付回调 → 进度更新 → 成团判断（tryCompleteTeam） |
| 4.4 | 拼团退款 | 三种退款策略（未支付/已支付未成团/已成团）+ 超时自动退款定时任务 |
| 4.5 | 回调通知 | HTTP/MQ 两种成团通知 + 定时补偿 |
| 4.6 | 拼团首页 | 优惠试算 + 进行中队伍展示 |

**验收**：并发成团临界正确（无超团）；超时自动退单可靠；队伍状态流转正确。

### Phase 5：积分体系（Week 8）

**目标**：积分闭环。里程碑：**签到得积分 → 积分兑换抽奖次数/SKU → 下单积分抵扣**。

| # | 任务 | 内容 |
|---|------|------|
| 5.1 | 积分账户 | user_credit_account 创建与维护（累计/可用/冻结） |
| 5.2 | 积分流水 | 正向/逆向交易记录（out_biz_no 防重） |
| 5.3 | 行为返利 | 签到得积分、购物返积分（行为配置化） |
| 5.4 | 积分兑换 | 兑换抽奖次数、兑换 SKU 商品（事务+MQ 最终一致 7 步流） |
| 5.5 | 积分在订单中使用 | 下单积分抵扣（与优惠券互斥/叠加规则见矩阵） |

**验收**：积分调整原子防透支；兑换流程完整闭环；互斥矩阵规则生效。

### Phase 6：优惠券系统（Week 9）

**目标**：券全链路。里程碑：**运营发券 → 用户领券 → 下单锁券 → 支付核销 → 退单退券**。

| # | 任务 | 内容 |
|---|------|------|
| 6.1 | 券模板管理 | 满减/折扣/运费/商品券 CRUD + 发布/停用 |
| 6.2 | 发券渠道 | 手动领取 + 活动发放 + 签到赠送 + 新人自动发 |
| 6.3 | 领券/用券 | 领券（校验限领/库存）→ 锁券（下单）→ 核销（支付成功） |
| 6.4 | 退券逻辑 | 订单取消/退款时券的退回策略（→REFUNDED 可再使用） |
| 6.5 | 最优券计算 | `calculateBestCoupon()`（先贪心后组合） |
| 6.6 | 过期处理 | XXL-Job 定时扫描 → EXPIRED |
| 6.7 | 券与积分互斥 | 下单计算优先级：拼团折扣 > 优惠券 > 积分抵扣 |

**验收**：锁券与订单同事务；退款退券可再用；最优券计算正确。

### Phase 7：订单履约（Week 10）

**目标**：发货→物流→确认收货闭环。里程碑：**ERP 发货 → 快递鸟轨迹 → 自动签收 → 订单完成**。

| # | 任务 | 内容 |
|---|------|------|
| 7.1 | 发货管理 | ERP 填写物流单号 → 订单 SHIPPED |
| 7.2 | 物流查询 | 对接快递鸟 API → 订阅轨迹 → 回调更新 |
| 7.3 | 物流补偿 | 定时轮询未签收订单最新物流状态 |
| 7.4 | 自动确认收货 | 签收后 N 天自动确认（如 7 天） |
| 7.5 | 订单完成 | DEAL_DONE → 可评价/可申请售后 |
| 7.6 | 订单评价 | 评分 + 文字评价（简易版，可选） |

**验收**：轨迹完整；签收自动转 DEAL_DONE；物流补偿可靠。

### Phase 8：售后体系（Week 11）

**目标**：售后全流程。里程碑：**申请退款/退货 → 审核 → 退款+退券+退积分**。

| # | 任务 | 内容 |
|---|------|------|
| 8.1 | 仅退款 | 申请 → 审核 → 退款（原路退回）+ 退券 + 退积分 |
| 8.2 | 退货退款 | 申请 → 审核 → 用户寄回 → 确认收货 → 退款+退券+退积分 |
| 8.3 | 售后状态机 | 完整状态流转 + 事件时间线 |
| 8.4 | 拒绝售后 | 审核拒绝 → 原因通知 |

**验收**：仅退款审核通过自动退款；退货退款流程完整；逆向用本地消息表+MQ 最终一致。

## 4. 依赖关系

```
Phase 1（骨架）            ← 无前置（基础）
Phase 2（搜索+购物车）      ← Phase 1（商品模块）
Phase 3（抽奖）            ← Phase 1（用户/鉴权）；活动表依赖 Phase 1 建表
Phase 4（拼团）            ← Phase 1（订单/支付回调）；折扣引擎独立
Phase 5（积分）            ← Phase 1（用户账户表）；Phase 3（兑换抽奖次数）
Phase 6（优惠券）          ← Phase 1（订单事务）；Phase 5（积分互斥规则）
Phase 7（履约）            ← Phase 1（订单状态机）
Phase 8（售后）            ← Phase 1（支付退款）；Phase 6（退券）；Phase 5（退积分）
Phase 9（首页+消息）       ← Phase 3/4（活动 Tab 数据）
Phase 10（风控+监控）      ← 全部业务（横切）；分库分表可提前铺
Phase 11（ERP）            ← 各业务模块（活动/策略/券/商品/订单/售后/首页）
Phase 12（压测+收尾）      ← 全部完成
```

## 7. 风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| 优惠券+积分+折扣互斥/叠加规则易乱 | 金额计算错误 | 先定规则矩阵，`calculateFinalPrice()` 统一入口（SRS §11.5） |
| 拼团并发成团临界 bug | 超团/退款错误 | 直接复用开源 group-buy-market 成熟方案 |
| 优惠券最优解算法复杂 | 计算性能/正确性 | 先贪心（单张最大优惠），后续优化组合遍历 |
| 售后退款+退券+退积分事务一致性 | 资金/资产不一致 | 本地消息表 + MQ 最终一致，不追求强一致 |
| 16 周战线长易放弃 | 项目中断 | 每 Phase 可独立演示，做完即有所得 |
| 微信/支付宝/快递鸟第三方联调受阻 | 阶段阻塞 | 沙箱/Mock 先行；内网穿透工具提前配置 |
| 一人多任务并行压力 | 交付延期 | 严格按依赖顺序；Phase 2/9 等低依赖阶段可弹性排期 |
